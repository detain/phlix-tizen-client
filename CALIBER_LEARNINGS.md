# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[pattern]** `@phlix/ui` and `@phlix/contracts` are pinned, pre-built GitHub deps (minified `dist/`). To confirm what the library actually exports or consumes, grep/sed its bundles under `node_modules/@phlix/ui/dist/*.js` rather than guessing — e.g. `usePlayerStore-*.js` lists the player-store members (`playing`, `play`, `pause`, `seekBy`, `closePlayer`), `Player-*.js` reads `phlixConfig.playerHlsConfig` into hls.js, and `phlix-ui.js` holds `useSpatialNav`. Do this before adding a `createPhlixApp` config key or calling a store action.
- **[gotcha]** `installTizenBridge` / the 2nd-app SpatialNavHost mount read `$pinia` and `$router` off `app.config.globalProperties`. This IS valid with the pinned deps: pinia sets `globalProperties.$pinia` and vue-router 5.1.0 sets `globalProperties.$router`/`$route` on `app.use(...)`. If a review claims `$router` isn't registered, verify against the installed version first (`grep globalProperties node_modules/vue-router/dist/vue-router.cjs`) — older vue-router majors dropped these Options-API globals, so the claim is version-dependent.
- **[gotcha]** `.claude/rules/*` and `.claude/skills/*` are Caliber-managed and auto-regenerated by `caliber refresh` on commit. They may still describe the OLD webpack/Jest/`app/js/**` architecture — do NOT hand-edit them to fix stale docs (edit `CLAUDE.md`/`AGENTS.md`/`DEVELOPER.md`/`README.md` instead and let Caliber resync).
- **[pattern]** When a subagent code review emits a HIGH/blocker finding, corroborate it against the resolved dependency tree in `node_modules` before acting — in this session the reviewer's top "runtime blocker" (`$router` missing from globalProperties) was refuted by a one-line grep of the installed vue-router 5.1.0 dist.
- **[pattern]** After doc/code edits, re-verify the whole gate in one shot: `npx vue-tsc --noEmit`, `npx vitest run`, `npx eslint .` (all must exit 0). Use `${PIPESTATUS[0]}` to capture the real exit code when piping through `tail`/`grep`.
- **[pattern]** To confirm a NAMED export (and that the installed tag actually ships it) before importing from `@phlix/ui`, grep its type bundle: `grep -oE "buildAdminRoutes|LibraryScanPage|MenuItem|..." node_modules/@phlix/ui/dist/index.d.ts` and verify the installed version with `node -p "require('./node_modules/@phlix/ui/package.json').version"`. v0.53.0 exports `buildAdminRoutes`, `buildHubAdminRoutes`, `LibraryScanPage`, `MyServersPage`, `FederationPage`, `ManageSharesPage`, `MenuItem`.
- **[gotcha]** `createPhlixApp` renders NO top-bar nav at all (Browse/Settings AND the admin-gated entry) unless you pass a `menu: MenuItem[]`. To add the admin section you supply BOTH `menu` (with a `{ requiresAdmin: true }` Admin entry — the shell hides it for non-admins, and the API is gated server-side anyway) and `extraRoutes` (e.g. `[...buildAdminRoutes(), { path: '/app/library/scan', ... }]`). Extra-route paths carry the full `/app` prefix because the router's history base is `/`.
- **[gotcha]** `tests/unit/main.test.ts` mocks `@phlix/ui` with an explicit object literal (`vi.mock('@phlix/ui', () => ({ ... }))`). Any NEW named import you add to `src/main.ts` (e.g. `buildAdminRoutes`, `LibraryScanPage`) must be added as a stub to that mock, or the import resolves to `undefined` and `boot()` throws under vitest. Return marker values from the stubs so the boot-wiring test can assert they were forwarded into `createPhlixApp`.
- **[gotcha]** Codacy Static Code Analysis is a non-blocking/advisory PR check on this repo — it can report `fail` while Build Check, ESLint, and Tests all pass, and the PR is still mergeable. Gate merges on the GitHub Actions checks, not Codacy.
- **[pattern]** To confirm a NAMED export (and that the installed tag actually ships it) before importing from `@phlix/ui`, grep its type bundle: `grep -oE "buildAdminRoutes|LibraryScanPage|MenuItem|requireConnection|onConnectionChange|useConnectionStore|..." node_modules/@phlix/ui/dist/index.d.ts node_modules/@phlix/ui/dist/app/types.d.ts` and verify the installed version with `node -p "require('./node_modules/@phlix/ui/package.json').version"`. Note `createPhlixApp`'s CONFIG keys (`requireConnection`, `onConnectionChange`) live in `dist/app/types.d.ts`, while top-level exports (`useConnectionStore`, `buildAdminRoutes`) live in `dist/index.d.ts` — grep both.
- **[gotcha]** Bumping a `github:`-pinned dep is a TWO-step operation: editing the version in `package.json` does NOT re-fetch the new ref. After the edit, run `npm install "@phlix/ui@github:detain/phlix-ui#v0.54.0" --save` to force-resolve, then confirm with `node -p "require('./node_modules/@phlix/ui/package.json').version"` before trusting any export grep.
- **[gotcha]** Do NOT use `#` as the `sed` delimiter when the pattern contains `#` — `sed -i 's#github:detain/phlix-ui#v0.53.0#...#'` silently no-ops because the embedded `#v0.53.0` terminates the expression early. Either pick a delimiter the string lacks (e.g. `s|...|...|`) or just use the Edit tool for a single unique line.
- **[convention]** The `@phlix/ui` version pin is duplicated across FOUR files: `package.json` plus `README.md` (badge URL + dependency list), `CLAUDE.md`, and `DEVELOPER.md` (both prose and a "must export" line). When bumping, `grep -rn "v0.5[0-9].0" README.md DEVELOPER.md CLAUDE.md` then `sed -i 's/v0.53.0/v0.54.0/g'` all three docs so they don't drift from `package.json`.
- **[gotcha]** Do NOT add `cache: 'npm'` to `actions/setup-node` in this repo's workflows — `package-lock.json` is gitignored (CI uses `npm install`, not `npm ci`), and the cache action errors when it can't find a lock file. Omit the `cache` key entirely.
- **[gotcha]** `npm run package` mutates the git-tracked `package/` directory with freshly content-hashed asset filenames, so after running it `git status` shows the old `package/assets/*.js` as deleted and pollutes `git add -A`. When committing only a workflow/source change, `git add` the specific file(s), then restore the dir with `git checkout -- package/ && git clean -fdq package/` and verify `git show --stat HEAD` contains only the intended file.
- **[pattern]** Rolling "latest" release for client builds: GitHub Actions artifacts are ALWAYS served zipped, so to offer a raw downloadable build asset (`.wgt`/`.exe`/`.phar`) publish a GitHub Release instead. The pattern is a `release-latest` job gated on `github.event_name == 'push' && github.ref == 'refs/heads/master'` that runs `gh release delete latest --yes --cleanup-tag || true` then `softprops/action-gh-release@v3` with `tag_name: latest`, `prerelease: true`, `make_latest: false`, `target_commitish: ${{ github.sha }}`. Mirrors the other phlix clients.
- **[pattern]** Validate a GitHub Actions workflow before pushing with `python3 -c "import yaml; yaml.safe_load(open('.github/workflows/build.yml'))"`, and dry-run the packaging/zip steps locally (`npm run package` → `cd package && zip -rq -X /tmp/test.wgt .`) so CI failures are caught before the PR.
